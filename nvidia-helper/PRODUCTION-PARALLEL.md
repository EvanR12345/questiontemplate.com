# Production parallel setup

October 13 follow-up: production forecasts now follow the helper's actual CPU or NVIDIA renderer, including an explicit CPU fallback. Render-history format 2 separates backends, encoder settings, worker limits and effects; ambiguous old samples remain saved but do not train the new rendering estimate. Narration metadata counts only current script/voice signatures with a saved audio path and valid duration. Playback previews request metadata first; pausing while an expired viewing link renews keeps the renewed player paused. Sampled QC selection no longer flattens every shot for every decision. An eight-round, 80-chapter synthetic comparison preserved all 8,002 selections and reduced local selection time about 12 times; this is not an inference, API or full-video speed measurement. Practical every-image checks remain the default.

The managed RTX 5090 setup uses two independent ComfyUI Python processes on one GPU, with four bounded client request slots. Each process still executes its own queue. Both share the same pinned model files and existing image environment; no second Torch environment is installed. Startup must verify distinct process IDs, both APIs and exactly one required GPU before submitting images.

`comfyModelCopies=2`, `studioAudioLookahead=true` and `studioRenderOverlap=true` select this setup. The recommended director preset uses Standard/Balanced Luna, four shared API slots, 128-sentence factual groups and Small visual groups. It preserves model, visual style, reference images, image cadence, voice, scripts, manual edits and spending limits. Explicitly disabled visual checks stay disabled. Local narration and rendering share one lane; next-chapter narration can overlap current directing, and a ready chapter can render while later cloud work runs. Story facts and chapter handoffs remain ordered.

Startup preserves the container's assigned CUDA device/library environment instead of relying on SSH login-shell variables. A real CUDA tensor smoke test runs before model downloads. Process discovery verifies the Python listener rather than a supervisor mentioning `main.py`. An absent default launcher can be recovered using its existing image-managed environment; occupied ports and custom launch arguments are not replaced. Bootstrap diagnostics redact credentials and URLs. Unknown remote operations block replay; only explicit capacity rejections with confirmed shutdown may retry within the saved availability window.

An authenticated creator can transfer a freshly allocated worker through `ownedWorkerReceipt` on a full-story job. It must match the configured pod, project, exact saved GPU cap, unique test-worker name and recent provider creation time. This preserves scarce capacity without adopting an unrelated running pod. The creator retains emergency shutdown responsibility until Studio's durable ownership/deadline receipt is confirmed. Normal website generation does not require this field.

Long source sentences can provide additional visual cut opportunities within their existing narration bounds. Complete source sentences remain the factual authority, exact words are preserved, and intra-sentence timing is explicitly estimated when word alignment is unavailable. No image cadence reduction or invented events is used to work around a cut-slot shortage.

Practical visual review distinguishes narrated facts and canonical identity/state from director-created staging. A staging variation can remain an advisory without being called a pass; wrong identities, explicit reversed story actions and unusable images remain blocking. New explicit reviews retain superseded findings. Review-format versions separate timing observations. Existing manual acceptances are preserved.

The planner follows actual copies, request slots and phase overlap. Incompatible historical director calibrations are labeled references; fresh compatible observations can inform estimates. It can use the configured verified worker's last observed compute quote without a new network request or rental. That quote is dated, not a current availability guarantee; storage remains separate. Failed, cached, paused and interrupted samples remain visible and are excluded from fresh speed calibration.

## October 13 verification

A complete two-chapter, 188-word test produced an 82.05-second narration video: H.264, 1280×720, 30 fps, AAC audio. All 11 selected PNGs decoded at 1280×720 and were visible. A full MP4 decode passed. Worker 0 contributed six selected images and worker 1 five. A three-second live pause/resume retained the same job and all six previously completed selections. The full result and project were synchronized to private Google storage.

The successful worker used the official CUDA-12.8 ComfyUI image with unchanged FLUX.2 Klein 4B FP8 weights, four steps, guidance 1 and character references. Preserving the image's GPU environment resolved the CUDA initialization failure observed through SSH. This does not establish that CUDA 13 is incompatible.

Verified cold preparation took 155.8 seconds. The successful rental lasted 306.1 seconds, including image loading, reference-conditioned generation, reviews, a pause and two repair attempts. Its estimated compute charge was $0.0587 at the observed $0.69/hour quote. Final saved-asset assembly and cloud completion took 40.7 seconds; measured chapter renders were 5.3 and 6.3 seconds and full-story assembly 1.7 seconds, with the GPU stopped.

Across setup failures, generation, repairs and re-review, recorded compute/API estimates were $0.13169 + $0.00999 = $0.14168. A $0.25 storage allowance remained reserved within the $2 test cap. These are recorded estimates, not a reconciled provider invoice. All task-created GPU instances were confirmed stopped; retained resources were not deleted. Five advisory visual findings remain, with no blocking major finding after the source-authority recheck. The earlier major finding and repair history are preserved.

This short test proves actual two-process operation and complete export, not a guaranteed two-hour-video finish time or a measured whole-production speedup. Narration/plans were reused during startup retries; the pause and failures must not train fresh throughput estimates. Original projects and assets were preserved; only the authorized recommended settings preset changed the existing target project.
