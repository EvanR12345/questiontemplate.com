Same image work, less connection overhead

The image client reuses HTTP connections to the same worker. Model weights, steps, sampler, seeds, reference conditioning, resolution and decoding stayed fixed. The four runs followed an alternating before/after/after/before order, with fresh worker processes and warmups for each run.

The 24 matched cases came from 12 prompts and two seed sets. All 96 measured images used fresh sampling and decoding; corresponding output pixels matched exactly. Three text-encoder cache hits occurred: one with original connections and two with persistent connections. Startup and eight warmup images are excluded from batch times and included in spending.

The small repeat set and text-cache imbalance limit attribution of the observed 4.00% batch difference. This supplies no new QC latency result and does not establish a 4% reduction in the complete video's duration.

Saving stays durable

Saving still reads the actual current file, checks its revision, writes the exact previous backup, publishes the new project atomically and queues the archive. The change avoids decoding the same unchanged file twice. All final project and backup bytes matched in the 40-mutation comparison.

The large-file check uses a 32-byte fingerprint rather than retaining the raw oversized project. Its final documents matched except for the updated timestamp. Director checks still read fresh saved data; changed source, settings, identity or prior story state trigger the original signature check. Full request context and signature values are preserved.

Final assembly of two hours of existing media

This test joined a 12-second chapter clip and its existing narration 600 times, producing a 7,200-second, 216,000-frame video at 720p30. Joining video and muxing audio in one pass removed a separate silent intermediate. The complete 3,116,431,997-byte output matched exactly.
